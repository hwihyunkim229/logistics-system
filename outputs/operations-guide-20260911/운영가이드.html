물류 시스템 운영 가이드

어디에 입력하고, 어떤 화면에서 확인하는지 정리한 사용 안내

2026년 9월 11일 개발 버전을 기준으로 작성했습니다. 운영 중인 버전이 다르면 일부 화면이나 기능은 다를 수 있습니다.

1. 먼저 알아두면 편한 것

이 시스템에는 이름이 비슷한 재고 화면이 여러 개 있습니다. 수불재고에 입력한 수량과 대여재고에 입력한 수량은 따로 관리되므로, 숫자가 다르다고 바로 오류는 아닙니다. 먼저 어떤 업무의 재고를 보고 있는지 확인해 주세요.

MRP에서 말하는 보유재고는 수불재고를 기준으로 계산한 수량입니다. 가계상재고나 제품 입출고 화면의 숫자를 가져오는 것은 아닙니다.

품목코드는 품목을 구별하는 번호이고, 품명은 사람이 읽는 이름입니다. 예를 들어 코드가 SL-H-AS-00032이고 품명이 RING_PBA_SIZE_10입니다. MRP는 이 코드를 보고 같은 자재인지 찾습니다. 이름이 조금 달라도 코드가 같으면 연결됩니다.

엑셀은 꼭 해당 화면에서 내려받은 양식을 사용해 주세요. 화면마다 필요한 열과 저장 방식이 다릅니다. 특히 BOM은 기존 내용을 전부 바꾸지만, 품목 관리는 없는 품목만 추가합니다. 자세한 차이는 4번 표에 모아두었습니다.

  • 5. 등록된 BOM의 제품명으로 생산계획을 작성합니다.
  • 6. MRP에서 대표 품목을 골라 소요량·등급·보유재고를 대조합니다.
  • 7. 제품 물류·대여·Workflow는 각 업무의 별도 시작 재고와 진행 건을 준비합니다.

품명을 바꾸면 다른 화면도 바뀌나요?

  • MRP 재고 매칭은 품명이 아니라 코드 기준입니다. 품명만 달라도 코드가 맞으면 연결됩니다.
  • 코드에 들어간 공백은 제거하고 비교합니다. 다만 대소문자나 하이픈·밑줄이 다르면 같은 코드로 인식하지 않을 수 있습니다.
  • 품목 관리의 수정 기능은 기존 코드가 정확히 일치하는 가계상재고, 가계상 입출고 이력, BOM, 수불재고, 자재기준정보 및 자재 메모에 변경을 전달합니다.
  • 품목 관리의 엑셀 업로드는 기존 코드를 건너뜁니다. 화면 수정과 동일한 갱신 기능이 아닙니다.
  • 자재기준정보 등록이 품목 관리에 신규 품목을 자동 생성하지는 않습니다.
  • Workflow는 별도 품목 설정과 품명 일관성 검사도 사용합니다. 품목 관리나 BOM 업로드가 Workflow 설정까지 자동 동기화한다고 가정하지 마세요.

5. 화면별 엑셀 작성법

5.1 품목 관리

정확한 열 이름: 품목코드 / 품명 / Rev. BOM의 품목명과 혼동하지 않습니다.

  • 품목코드·품명은 실제 값을 입력하고, 리비전이 없더라도 Rev 열은 유지합니다.
  • 기존 코드를 수정하려면 품목 관리 화면의 수정 기능을 사용합니다.
  • 예: SL-H-AS-00032 / RING_PBA_SIZE_10 / A.
  • 코드가 숫자처럼 보이면 엑셀에서 텍스트 형식으로 보존해 앞자리 0이 사라지지 않게 합니다.

5.2 가계상재고

  • 초기 생성: 품목코드 / 구분. 품목 관리에 없는 코드는 제외됩니다. A·B·F 등급 재고를 각각 0으로 만듭니다.
  • 수량 업로드: 품목코드 / 구분 / 등급 / 수량. 코드+등급이 같은 기존 행은 업로드 수량으로 바뀝니다.
  • 수량 빈칸은 0으로 처리됩니다. 예를 들어 기존 100개에 20을 업로드하면 120개가 아니라 20개가 됩니다.
  • 품명과 Rev는 품목 관리에서 가져옵니다. 분류는 화면의 구분 값에 맞춰 작성합니다.

5.3 수불재고

필수 열: 품목코드 / 창고구분. 추가 열: 구분 / LOT / Grade / 수량 / 비고.

  • 창고구분은 업무 화면의 창고재고 / 제공재고 / 외주재고를 정확히 사용합니다.
  • 창고재고의 실제 수량을 넣을 때는 Grade와 수량을 함께 작성합니다.
  • 창고재고에서 Grade가 비어 있으면 A·B·F 등급 항목만 만들어질 수 있습니다. 수량을 넣으려던 등급이 빠지지 않았는지 확인해 주세요.
  • 수량 열이 없으면 0으로 처리하므로 수량 갱신 파일에서 열을 삭제하지 않습니다.
  • 원자재는 LOT를 빈 값으로 정리합니다. 같은 코드·창고·등급의 원자재를 LOT만 달리해서 별개 재고로 만들 수 있다고 가정하면 안 됩니다.
  • 품명·Rev는 품목 관리/가계상재고 조회로 채워집니다. 조회 가능한 품명이 없으면 해당 행은 제외됩니다.
  • 초기 생성 기능은 수량 등록 기능이 아닙니다. 기본 수량은 0입니다.

5.4 제품 물류 입고·출고

권장 열: 입고 화면은 입고일자 / Serial / Size, 출고 화면은 출고일자 / Serial / Size / 출고처. 선택적으로 구분을 사용합니다.

  • 제품은 파일의 제품명 열이 아니라 업로드한 화면의 제품 분류로 저장됩니다.
  • 날짜 열은 이름에 입고 또는 출고가 포함된 첫 번째 열을 선택합니다. 관련 열을 여러 개 두거나 출고처를 날짜 열보다 먼저 두지 말고 내려받은 양식을 사용합니다.
  • Serial은 영문 serial이 들어간 열로 찾습니다. S/N만 쓴 임의 양식은 같은 의미로 인식하지 않습니다.
  • 날짜는 엑셀 날짜 또는 2026-09-11, 2026.09.11, 2026/09/11 형식으로 작성합니다.
  • Size는 숫자로 입력합니다. 열 자체는 필요하고 값이 없는 행은 사이즈 미입력으로 처리될 수 있습니다.
  • 빈 Serial 검사가 충분하지 않은 코드가 있으므로 빈 행·빈 Serial은 파일에서 제거합니다.
  • 같은 파일을 다시 올리기 전에는 이미 등록됐는지 확인해 주세요. 기존 기록을 고치는 대신 같은 입출고가 한 번 더 등록될 수 있습니다.

5.5 BOM

권장 열: 제품명 / 품목코드 / 품목명 / 소요량.

허용 별칭: 제품명은 Product, product_name; 품목코드는 Item Code, component_code; 품목명은 Item Name, component_name; 소요량은 Qty, qty도 인식합니다.

  • 네 열은 모두 있어야 합니다. 제품명·코드·소요량이 비거나 소요량이 0 이하인 행은 계산용 등록 대상에서 빠집니다. 품목명 값이 비어도 코드상 등록 가능하지만 업무상 입력을 권장합니다.
  • 모든 제품을 포함한 전체 BOM 파일을 업로드합니다. 기존 전체 BOM을 교체합니다.
  • 중복 구성품 행을 자동 합쳐 제거하지 않으므로 같은 제품·구성품의 중복 소요량을 확인합니다.
  • 제품명을 바꾸면 생산계획의 제품 선택 목록도 바뀝니다. 이미 저장된 과거 계획의 제품명은 자동 변경되지 않습니다.
  • 예: 완제품_10호 / SL-H-AS-00032 / RING_PBA_SIZE_10 / 1.
  • 2026-09-11 확인한 첨부 BOM은 코드 열에 품명, 품명 열에 코드가 들어 있었습니다. 값의 위치까지 반드시 대조합니다.

5.6 생산계획

  • 화면에서 월을 선택해 전용 엑셀을 다운로드합니다. 6번째 행을 헤더로 읽으며 사이즈 열을 찾습니다. 제목 행을 추가하거나 삭제하지 않습니다.
  • 사이즈 열의 각 행 값은 실제로 생산계획 제품명으로 저장됩니다. 제품명을 임의로 줄이거나 호수만 입력하지 않습니다.
  • 날짜 열 아래에 1 이상의 정수 수량을 입력합니다. 소수 수량은 의도대로 보존되지 않으므로 사용하지 않습니다.
  • 같은 제품명+날짜가 있으면 수량 대체, 없으면 추가됩니다.
  • 0 또는 빈칸을 업로드해도 기존 수량이 있는 계획은 삭제되지 않습니다. 계획 취소는 별도 처리 여부를 담당자와 확인해야 합니다.
  • 현재 화면은 월 전체 일별 조회와 주별 합계를 지원합니다. 월 밖의 날짜는 해당 월 합계에 포함하지 않으며, 검색 기간 조회 시에는 표시 기간 기준입니다.
  • ‘생산계획 없는 제품 숨기기’는 화면 필터입니다. 데이터 삭제나 MRP 계획 취소 기능이 아닙니다.

5.7 자재기준정보

필수 열: 품목코드 / 품목명 / 업체명 / MOQ + 리드타임 열.

  • 리드타임 열은 LT(주), LT, L/T, L/Time, 리드타임, Lead Time 중 하나를 사용합니다. 기본 양식의 LT(주)를 권장합니다.
  • 단위는 주입니다. 일 단위 숫자를 그대로 넣지 않습니다.
  • 품목코드가 없는 행은 제외합니다. 리드타임 빈칸은 0입니다. 업체와 품명은 실무상 반드시 채웁니다.
  • MOQ는 최소 주문수량입니다. 이 시스템은 MOQ 단위로 맞춰 발주량을 계산합니다. 예를 들어 40개가 부족하고 MOQ가 30개라면 60개 발주를 권합니다.
  • 코드별로 기존 이름·업체·LT·MOQ를 갱신하므로 빈 값으로 덮어쓰지 않도록 확인합니다.

5.8 대여 재고·입출고

재고 업로드: 화면에서 분류를 선택한 뒤 품목코드 / 품명 / 수량을 입력합니다. 동일 분류+코드의 이름·수량을 대체합니다.

입출고 업로드는 다운로드 파일의 아래 13개 열을 모두 유지합니다.

이력ID / 구분 / 분류 / 품목코드 / 품명 / 수량 / 본부 / 부서 / 요청자 / 사이즈 / S/N / 불출일자 / 비고

  • 신규 행은 이력ID를 비웁니다. ID가 있는 기존 행은 건너뛰며 수정하지 않습니다.
  • 구분은 입고/출고 또는 IN/OUT, 수량은 1 이상의 정수입니다.
  • 분류+품목코드가 대여재고에 있어야 하며, 본부·부서는 시스템 선택 목록과 서로 일치해야 합니다.
  • 요청자·사이즈·S/N을 입력합니다. 사이즈도 시스템 허용값을 사용합니다.
  • 날짜는 내려받은 양식 형식을 유지합니다. 품명·비고 열은 삭제하지 않으며 저장 이력의 품명은 등록된 재고에서 가져옵니다.
  • 재고가 음수가 되는 업로드는 거절됩니다. 신규 행을 ID 없이 다시 올리면 추가 처리될 수 있습니다.

5.9 Workflow 구매 입고

필수 열: Product / 품목코드 / 품명 / LOT / 입고 수량 / 입고 일자.

  • Product·품목코드·품명·LOT·수량은 값이 필요합니다. 수량은 1 이상의 정수로 작성합니다.
  • 입고 일자 열은 유지하고 실제 입고 시각을 입력합니다. 날짜가 없는 경우의 자동 현재시각 처리에 의존하지 않는 것을 권장합니다.
  • LOT는 입고 건을 구분하는 핵심 값입니다. 같은 품목이라도 입고 건별 LOT를 관리합니다.
  • 기존 Workflow와 코드·품명의 일관성도 확인합니다. 표준 품명을 사용합니다.
  • 각 행마다 신규 Workflow 번호를 발급합니다. 기존 건을 엑셀로 갱신하는 기능이 아닙니다.
  • 파일 중간에서 오류가 나더라도 앞부분은 이미 등록됐을 수 있습니다. 이때는 구매 목록을 먼저 확인하고, 등록되지 않은 행만 다시 올려 주세요.

6. MRP 숫자는 어떻게 읽나요?

재고 포함 조건

수불재고 구분MRP 포함
창고재고A등급만
제공재고등급 제한 없이
외주재고등급 제한 없이
그 외 구분MRP 보유재고에서 제외

계산 순서:

  • 1. 제품의 계획 수량 × BOM 구성품 소요량으로 품목별 필요 수량을 구합니다.
  • 2. 같은 품목코드의 위 조건에 맞는 수불재고를 합산합니다.
  • 3. 연·월·주 필터가 있으면 선택 구간 앞의 계획 소요량을 차감해 가용재고를 구합니다. 차감 결과가 음수이면 0으로 표시합니다.
  • 4. 부족량 = 필요 수량 − 가용재고, 최소 0입니다.
  • 5. MOQ가 있으면 부족량을 MOQ 배수로 올려 권장 발주량을 계산합니다.

예: 필요 120개, 포함 재고 80개, MOQ 30이면 부족 40개·권장 발주 60개입니다. 기간 이전 소요량 20개를 추가 차감하는 조건이면 가용 60개·부족 60개가 됩니다.

MRP에 부족 수량이나 권장 발주량이 나와도 실제 발주가 자동으로 진행되는 것은 아닙니다. 계산만으로 수불재고 수량이 줄어들지도 않습니다. 실제 구매와 입출고는 해당 업무 화면에서 처리해야 합니다.

재고가 있는데 0으로 나올 때

  • 1. 생산계획 제품명과 BOM 제품명이 같은가?
  • 2. 코드 열에 품명을 넣지는 않았는가?
  • 3. BOM 코드와 수불재고 코드가 공백 정리 후 같은가?
  • 4. 재고가 가계상재고나 대여재고에만 있는 것은 아닌가?
  • 5. 창고재고가 B/F등급으로만 있는 것은 아닌가?
  • 6. 선택 기간 이전 계획 소요량을 차감했는가?
  • 7. 비교하는 대시보드 합계가 전체 카테고리 수량이고, MRP는 특정 BOM 품목인 것은 아닌가?

7. 구매부터 출하까지 처리하기

기본 단계: 구매 입고 → 수입 검사 의뢰 → 품질 입고 승인 → 품질 수입 검사 → 자재 확인 → 생산 요청 → 생산 승인 → 생산 완료 → 자재 확인 → 공정 검사 의뢰 → 공정 검사 → 자재 확인 → 포장 요청 → 포장 완료 → 최종 자재 확인 → 서비스 출하.

  • 구매 담당: 입고 건 등록 후 검사 의뢰 수량을 확인합니다. 현재 입고 수량보다 큰 수량을 의뢰할 수 없습니다.
  • 품질 담당: 의뢰된 건의 승인·검사 결과를 처리합니다.
  • 자재 담당: 각 완료 단계 이후 실물 수량을 확인하고 다음 단계로 요청합니다.
  • 생산 담당: 승인된 생산·포장 건의 완료 수량과 구성품·잔량을 확인합니다.
  • 일부 업무는 직접 포장 및 세트 생산·포장 경로를 제공합니다. 모든 항목이 항상 같은 중간 단계를 거치는 것으로 보지 않습니다.
  • 반려와 잔량 재사용은 전용 기능을 사용합니다. 원래 건을 삭제하고 새로 만드는 식으로 이력을 끊지 않습니다.
  • Workflow에서 생산·포장에 사용하는 구성품 정보는 MRP BOM과 별도로 관리합니다. BOM을 새로 올렸다고 Workflow 구성품도 바뀌는 것은 아닙니다.
  • Workflow에서 완료 처리한 건은 해당 업무의 진행 상태와 수량에 반영됩니다. 수불재고·가계상재고·제품 S/N 입출고도 함께 변경됐다고 생각하지 말고, 필요한 재고 처리는 각 화면에서 확인해 주세요.

8. 조회와 관리자 기능

  • 조회 필터는 화면이 지원하는 다중 선택으로 여러 값을 선택할 수 있습니다. 등록 폼의 단일 값 입력과 조회 필터를 혼동하지 않습니다.
  • 대시보드의 기간을 맞춘 후 다른 화면과 비교합니다. 제품 입출고는 이력 건수, 재고는 보유 수량이므로 합계 단위가 다를 수 있습니다.
  • 생산계획의 주별 전환은 합산 조회입니다. 업로드·저장 데이터는 날짜별 계획으로 유지됩니다.
  • 권한은 기능별 조회·수정·다운로드로 나뉩니다. 품목 관리 경로는 가계상재고 기능 권한에 묶여 있습니다. 버튼이 없거나 접근이 안 되면 관리자에게 기능 권한을 확인합니다.
  • 활동 로그는 업로드·수정·삭제 등의 업무 기록, 접근 감사 로그는 URL·요청 방식·상태코드 등의 요청 기록입니다.
  • 200 OK는 HTTP 요청 처리 성공입니다. 계산 결과의 정확성이나 AI 답변의 사실성을 증명하지 않습니다.
  • 브라우저/장치 문자열은 접속 환경의 단서입니다. 특정 실물 PC나 사람을 확정하는 식별자는 아닙니다.
  • AI 도우미 답변이 실제 화면과 다르면 질문·기간·품목코드를 함께 기록해 원본 화면과 코드 기준으로 확인합니다.

9. 업로드할 때 확인할 것

업로드 전

  • 1. 대상 화면의 최신 양식을 다운로드합니다.
  • 2. 필수 열 제목과 데이터 시작 행을 유지합니다.
  • 3. 제품명·품목코드·품명을 구분합니다.
  • 4. 창고/등급/LOT/날짜/분류를 확인합니다.
  • 5. 추가인지 교체인지 위 비교표로 확인합니다.
  • 6. 중요 수량 갱신·BOM 전체 교체 전 현재 화면을 다운로드해 비교본을 남깁니다.

업로드 후

  • 1. 서버 오류뿐 아니라 화면의 오류 메시지·제외 건수를 확인합니다.
  • 2. 대표 2~3개 품목의 이름·코드·수량을 원본과 대조합니다.
  • 3. 수량 대체 업로드는 기존 수량에 더해지지 않았는지 확인합니다.
  • 4. 생산계획은 0/빈칸이 기존 계획을 지우지 않았다는 점을 확인합니다.
  • 5. MRP는 동일 기간으로 다시 조회해 재고 포함 조건과 MOQ를 확인합니다.
